## Implementation

- `/admin/login` authenticates the separate username/password operator account. Creator sessions and workspace admin roles grant no access. The database allows only one operator account.
- `/admin/beta-requests` reads and writes through guarded `/api/admin/**` routes. Search, status counts, filters and 50-row pagination retain request identities and consent. Requested records can be invited, declined or reopened; invited records can be resent.
- Passwords use independent salted scrypt hashes. Opaque session tokens are stored only as SHA-256 hashes, expire after eight hours and are revoked on logout or credential replacement. Production cookies are HttpOnly, Secure and SameSite Strict. Login attempts are limited atomically across instances. Metadata bodies are bounded to 4 KiB and mutations require the same origin.
- Sends claim a persisted operation before calling Supabase. Replays do not send again, joined requests cannot be resent, and provider uncertainty retains its fence. Check status reads committed Auth email receipts. Provider acceptance is not a claim of inbox delivery.
- Auth triggers mark the matching request joined only after email confirmation and a real sign-in. Request insertion reconciles already active accounts; installation backfills existing accounts from the last known sign-in. Request submission itself grants no access. Public signup remains disabled.
